<Tip>
  Using an AI agent? [Add the MCP server](/mcp) and say "set me up": it does every step below for you. In the [TUI](/tui#get-started), run `subscriber` and it walks you through them.
</Tip>

The steps below use the CLI, the TUI or the REST API. Pick a tab on any step and the rest follow.

## 1. Sign in

Install the CLI and sign in. A browser opens once to confirm.

```bash
npm install -g @subscriber.dev/cli
subscriber login
```

The CLI saves your session in `~/.config/subscriber/config.json`. It needs Node.js 22.12 or later.

Your AI agent doesn't need it: [the MCP server](/mcp) signs in through your browser. To use the TUI, run `subscriber` with no arguments.

## 2. Pick a workspace and environment

A workspace is your team's account. Inside it, environments keep separate sets of data, such as production and staging, so testing never emails real people. Every workspace starts with a **Production** environment.

<Tabs>
  <Tab title="CLI">
    ```bash
    subscriber workspaces list
    subscriber workspaces use <workspaceId>
    subscriber environments list
    subscriber environments use <environmentId>
    ```

    Later commands run against the workspace and environment you picked. Create a workspace with `subscriber workspaces create "Acme"`.
  </Tab>
  <Tab title="TUI">
    Run `subscriber`, then choose a workspace and an environment. Press `n` to create either.
  </Tab>
  <Tab title="API">
    Pick the environment with the CLI, as in the CLI tab, then create an API key for it. A `full` key can do every step below:

    ```bash
    KEY=$(subscriber keys create "Quickstart" --access full)
    ```

    The key decides the environment, so requests don't name it. See [Authentication](/api-reference/introduction#authentication) for what keys can do.
  </Tab>
</Tabs>

## 3. Connect your email provider

Subscriber.dev sends through your own provider, so you keep your sending reputation and pay them directly. It works with any SMTP provider, or Cloudflare Email.

<Tabs>
  <Tab title="CLI">
    ```bash
    subscriber integrations set smtp --body '{
      "host": "smtp.resend.com",
      "port": 465,
      "secure": true,
      "fromEmail": "hello@acme.com",
      "fromName": "Acme",
      "user": "resend",
      "password": "re_..."
    }'
    ```

    For Cloudflare Email, use `subscriber integrations set cloudflare` with `accountId`, `apiToken`, `fromEmail` and `fromName`.
  </Tab>
  <Tab title="TUI">
    Open **Integrations**, press `n`, choose **SMTP** or **Cloudflare Email**, and fill in the form.
  </Tab>
  <Tab title="API">
    ```bash
    curl -X PATCH https://api.subscriber.dev/integrations/smtp \
      -H "x-api-key: $KEY" -H "content-type: application/json" \
      -d '{"host": "smtp.resend.com", "port": 465, "secure": true, "fromEmail": "hello@acme.com", "fromName": "Acme", "user": "resend", "password": "re_..."}'
    ```
  </Tab>
</Tabs>

The connection is checked before it's saved, and credentials are encrypted at rest. See [Sending](/sending) for other providers and how to stay out of the spam folder.

## 4. Create a workflow

This one sends a welcome email straight away and a follow-up two days later.

<Tabs>
  <Tab title="CLI">
    Save this as `welcome.json`:

    ```json welcome.json
    {
      "key": "welcome",
      "name": "Welcome",
      "steps": [
        {
          "type": "email",
          "subject": "Welcome to Acme",
          "body": "<p>Hey {{ subscriber.firstName | default: \"there\" }},</p><p>Thanks for signing up.</p><p><a class=\"button\" href=\"https://acme.com/start\">Get started</a></p>"
        },
        {
          "type": "email",
          "delayMs": 172800000,
          "subject": "How's it going?",
          "body": "<p>Just checking in. Reply to this email if you're stuck.</p>"
        }
      ]
    }
    ```

    ```bash
    subscriber workflows create --file welcome.json
    ```
  </Tab>
  <Tab title="TUI">
    Open **Workflows**, press `n`, and fill in the key, name and steps. Each step is an email or a webhook, with an optional delay.
  </Tab>
  <Tab title="API">
    With the same `welcome.json` as the CLI tab:

    ```bash
    curl -X POST https://api.subscriber.dev/workflows \
      -H "x-api-key: $KEY" -H "content-type: application/json" \
      -d @welcome.json
    ```
  </Tab>
</Tabs>

See [Workflows](/workflows) and [Templates](/templates) for everything a workflow can do.

## 5. Add a subscriber and trigger the workflow

A subscriber is someone you email. Triggering a workflow starts it for one subscriber, which is what your app would do when someone signs up.

<Tabs>
  <Tab title="CLI">
    ```bash
    subscriber workflows trigger welcome --email jane@acme.com --first-name Jane
    ```
  </Tab>
  <Tab title="TUI">
    Open **Subscribers** and press `n` to add Jane. Then open **Workflows**, choose **Welcome**, press `t` and enter her email.
  </Tab>
  <Tab title="API">
    In production you'll usually do this from your app's code, right after signup. Give your app a `limited` key, which can only add subscribers and trigger workflows: `subscriber keys create "Acme app"`.

    ```ts
    const api = "https://api.subscriber.dev";
    const headers = {
      "x-api-key": process.env.SUBSCRIBER_API_KEY,
      "content-type": "application/json",
    };

    await fetch(`${api}/workflows/trigger`, {
      method: "POST",
      headers,
      body: JSON.stringify({
        key: "welcome",
        subscriber: { email: user.email, firstName: user.firstName },
      }),
    });
    ```
  </Tab>
</Tabs>

Triggering a workflow for an email that isn't a subscriber yet creates them. To bring in existing subscribers, use `subscriber subscribers bulk` or ask your agent to import an export.

## 6. Check it sent

Each time a workflow is triggered it creates a run, which records what sent and what's still waiting.

<Tabs>
  <Tab title="CLI">
    ```bash
    subscriber workflows runs <workflowId>
    ```
  </Tab>
  <Tab title="TUI">
    Open **Workflows**, choose **Welcome** and press `r` to see its runs. **Run History** shows runs across every workflow.
  </Tab>
  <Tab title="API">
    ```bash
    curl https://api.subscriber.dev/workflows/$WORKFLOW/runs -H "x-api-key: $KEY"
    ```
  </Tab>
</Tabs>

Each run shows its status and which steps have sent.
