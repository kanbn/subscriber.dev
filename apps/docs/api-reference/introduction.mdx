The REST API is how your app talks to subscriber.dev, for example to add a subscriber and trigger a welcome email when someone signs up. The CLI and MCP server use the same API.

## Base URL

```
https://api.subscriber.dev
```

If you self-host, use your own API URL instead.

## Authentication

An API key proves the request comes from you. Every endpoint needs one in the `x-api-key` header.

```
x-api-key: <your API key>
```

To get one, run `subscriber login` with the [CLI](/quickstart). It signs you in through the browser and saves the key in `~/.config/subscriber/config.json`.

## Response codes

Subscriber.dev uses standard HTTP codes to indicate the success or failure of your requests.

In general, `2xx` HTTP codes correspond to success, `4xx` codes are for user-related failures, and `5xx` codes are for infrastructure issues.

| Status | Description                   |
| ------ | ----------------------------- |
| `200`  | Success                       |
| `400`  | Invalid parameters            |
| `401`  | Missing or invalid API key    |
| `404`  | Resource not found            |
| `429`  | Too many requests             |
| `500`  | Error with our infrastructure |

## Rate limits

Each API key, or agent signed in through MCP, can make 10 requests a second. Each IP address can make 20 requests a second across all of them. Over the limit, you get a `429`. Wait a second and try again. To add many subscribers at once, use the bulk endpoint, which takes 500 per request.

Inbound webhooks from email providers and Stripe have a higher limit, so a burst of bounces after a big broadcast isn't dropped.
