---
title: Connect your AI agent
description: "Run subscriber.dev from Claude, Cursor or any MCP client."
---

MCP (Model Context Protocol) is how AI agents like Claude and Cursor connect to other tools. Once you add subscriber.dev's MCP server, you can ask your agent to do anything you could do with the CLI or API. It gets the same tools as the API. Ask it to write a workflow, import subscribers or check how a broadcast went, and it calls subscriber.dev for you.

## 1. Add the server

The server URL is `https://mcp.subscriber.dev/mcp`.

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http subscriber https://mcp.subscriber.dev/mcp
    ```
  </Tab>
  <Tab title="Claude app">
    Add a custom connector in Claude's settings, with the URL `https://mcp.subscriber.dev/mcp`.
  </Tab>
  <Tab title="Other clients">
    Add a streamable HTTP server with the URL `https://mcp.subscriber.dev/mcp`.
  </Tab>
</Tabs>

## 2. Sign in

The first time your agent uses subscriber.dev, it opens your browser. Sign in with GitHub or an email link, then allow access. Your agent stays signed in from then on.

To disconnect an agent, run `subscriber agents list` to find it, then `subscriber agents disconnect <clientId>`.

### Use an API key instead

To skip the browser, use an API key. Get one by signing in with the [CLI](/quickstart#1-sign-in):

```bash
npm install -g @subscriber.dev/cli
subscriber login
```

The key is saved in `~/.config/subscriber/config.json` as `apiKey`. Send it in the `x-api-key` header:

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http subscriber https://mcp.subscriber.dev/mcp \
      --header "x-api-key: YOUR_API_KEY"
    ```
  </Tab>
  <Tab title="Cursor">
    Add this to `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "subscriber": {
          "url": "https://mcp.subscriber.dev/mcp",
          "headers": { "x-api-key": "YOUR_API_KEY" }
        }
      }
    }
    ```
  </Tab>
</Tabs>

## 3. Try it

New to subscriber.dev? Say "set me up". Your agent walks you through creating a workspace, connecting your email provider, and writing and sending a first welcome email to yourself.

Or start with something like:

- "Which workspaces and environments do I have?"
- "Connect my Resend SMTP account to production."
- "Send new signups three onboarding emails over a week."
- "Start a trial workflow when a Stripe trial starts, and stop it when they convert."
- "How did last week's broadcast do?"

Your agent asks for an environment the first time it needs one. Tell it which to use, such as production.

## What your agent can do

These are the tools your agent can call. You don't need to name them; just say what you want.

| Area | Tools |
| --- | --- |
| Account | `get_current_user`, `update_user`, `get_setup_status` |
| Workspaces | `list_workspaces`, `create_workspace`, `update_workspace`, `list_environments`, `create_environment` |
| Subscribers | `list_subscribers`, `get_subscriber`, `create_subscriber`, `update_subscriber`, `delete_subscriber`, `bulk_upsert_subscribers`, `update_subscriber_preferences`, `list_subscriber_tags`, `add_subscriber_tag`, `remove_subscriber_tag` |
| Workflows | `list_workflows`, `get_workflow`, `create_workflow`, `update_workflow`, `delete_workflow`, `trigger_workflow`, `list_workflow_runs`, `list_environment_runs`, `list_trigger_sources` |
| Emails | `send_test_email` |
| Images and videos | `upload_image`, `add_video` |
| Broadcasts | `preview_broadcast`, `trigger_broadcast`, `list_broadcasts`, `get_broadcast`, `pause_broadcast`, `resume_broadcast`, `cancel_broadcast`, `redispatch_broadcast` |
| Integrations | `list_integrations`, `get_integration`, `set_integration`, `set_primary_integration`, `delete_integration`, `list_inbound_events` |
| Analytics | `get_analytics` |
| Billing | `get_billing`, `create_checkout_link`, `create_billing_portal_link` |

Your agent can delete subscribers and workflows and send broadcasts. Most clients ask before running a tool; keep that on for anything that sends or deletes.
